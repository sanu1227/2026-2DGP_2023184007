# Sonic 애니메이션 뷰어 PRD

## 1. 개요

`sonic-sprite.png`에 포함된 Sonic 동작을 Pico2D로 자동 재생하는 애니메이션 뷰어를 개발한다.

실행 파일은 `sonic_animation_viewer.py` 하나로 구성한다. 프로그램은 각 동작을 5회 재생하고 1초 정지한 뒤 다음 동작으로 넘어간다. 마지막 동작까지 재생하면 첫 동작부터 다시 시작한다.

## 2. 목표 및 범위

### 목표

- 스프라이트 시트의 모든 동작을 빠짐없이 재생한다.
- 프레임을 확대해 동작을 쉽게 확인할 수 있게 한다.
- 프레임 전환과 캐릭터 기준점을 보정해 움직임을 부드럽고 자연스럽게 만든다.
- 동작 반복과 동작 사이 대기 시간을 일정하게 유지한다.
- 단계별 개발과 검증이 가능하도록 코드를 단순하게 구성한다.

### 범위 제외

- 게임 플레이
- 점수와 충돌 처리
- 캐릭터 이동 조작
- 사운드, 메뉴, 저장 기능
- 여러 소스 파일로 분리하는 구조

## 3. 실행 환경 및 리소스

| 항목 | 기준 |
|---|---|
| 언어 | Python |
| 그래픽 라이브러리 | Pico2D |
| 실행 파일 | `sonic_animation_viewer.py` |
| 이미지 파일 | 같은 폴더의 `sonic-sprite.png` |
| 이미지 크기 | `399×525` |
| 기본 창 크기 | `800×600` |
| 기본 확대 배율 | 3배 |
| 기본 프레임 간격 | 0.08초 |
| 화면 갱신 지연 | 0.005초 이하 |
| 캐릭터 기준선 | 화면 y=230 |

이미지 경로는 실행 위치를 기준으로 한 상대 경로를 사용한다.

## 4. 기능 요구사항

### FR-01. 초기화

- `open_canvas(800, 600)`으로 창을 연다.
- `sonic-sprite.png`를 로드한다.
- 초기 동작 인덱스, 프레임 인덱스, 반복 횟수를 0으로 설정한다.
- 이미지 로드에 실패하면 오류 원인을 출력하고 정상 종료한다.

### FR-02. 프레임 정의

스프라이트 시트 전체를 출력하지 않고, 각 동작의 프레임 영역을 코드에 직접 정의한다.

```python
# (source_x, source_y, width, height)
ACTIONS = [
    [(x, y, width, height), ...],
    ...,
]
```

- 하나의 내부 목록은 하나의 동작을 의미한다.
- 내부 목록 순서는 실제 재생 순서와 같다.
- 프레임 크기는 동작별 실제 영역에 맞춘다.
- 제목, 설명, 제작자 문구는 프레임에서 제외한다.

초기 조사 대상 행은 이미지 위쪽 기준으로 다음 좌표부터 확인한다.

`y=39, 79, 121, 167, 206, 238, 283, 326, 377, 426, 472`

Pico2D `clip_draw()`는 이미지 아래쪽 기준 좌표를 사용한다. 프레임을 이미지 위쪽 기준으로 기록할 경우 다음 식으로 변환한다.

```text
source_y = 525 - top_y - frame_height
```

### FR-03. 자동 재생

- 프로그램 시작 시 첫 동작의 첫 프레임부터 재생한다.
- 프레임 시간이 0.08초 이상이면 다음 프레임으로 이동한다.
- 한 루프에서 누적 시간이 프레임 간격을 여러 번 넘으면 누락된 프레임을 순서대로 처리한다.
- 동작의 마지막 프레임에 도달하면 해당 동작의 반복 횟수를 1 증가시킨다.
- 반복 횟수가 5보다 작으면 같은 동작의 첫 프레임으로 돌아간다.
- 반복 횟수가 5이면 마지막 프레임을 유지한 채 1초 대기 상태로 전환한다.
- 1초가 지나면 다음 동작의 첫 프레임을 재생한다.
- 마지막 동작 다음에는 첫 동작으로 순환한다.

### FR-04. 화면 출력

- 현재 프레임을 화면 중앙에 배치한다.
- 프레임은 기본 3배로 확대한다.
- 프레임 크기가 달라도 캐릭터 발 위치가 화면 `y=230` 기준선에 놓이도록 배치한다.
- 확대 비율과 프레임 비율을 유지해 캐릭터가 찌그러지지 않게 한다.
- 확대 후에도 화면 밖으로 잘리지 않도록 위치를 계산한다.
- 프레임 전환은 시간 기반으로 처리한다.
- 화면 갱신은 `delay(0.005)` 이하로 처리해 입력과 애니메이션 갱신 지연을 줄인다.

## 5. 상태 및 데이터

### 상태

| 상태 | 동작 |
|---|---|
| `PLAYING` | 현재 동작의 프레임을 재생한다. |
| `PAUSE_BETWEEN_ACTIONS` | 동작을 5회 재생한 뒤 1초 대기한다. |

### 필수 상태 변수

| 변수 | 의미 |
|---|---|
| `action_index` | 현재 동작 번호 |
| `frame_index` | 현재 동작의 프레임 번호 |
| `repeat_count` | 현재 동작을 완료한 반복 횟수 |
| `frame_elapsed` | 현재 프레임이 표시된 누적 시간 |
| `pause_elapsed` | 동작 사이 대기 누적 시간 |
| `GROUND_Y` | 모든 프레임의 하단을 맞추는 화면 기준선 |

시간은 `get_time()`으로 계산한다. `sleep()`으로 게임 루프 전체를 멈추지 않는다.

## 6. 파일 내부 구조

단일 파일 안에서 다음 역할을 구분한다.

1. 상수와 `ACTIONS` 프레임 데이터
2. 창과 이미지 초기화
3. 시간에 따른 애니메이션 상태 갱신
4. 현재 프레임 그리기
5. 창 닫기 입력과 메인 루프
6. 캔버스 종료 및 리소스 정리

권장 함수 역할은 `initialize()`, `update_animation()`, `draw_current_frame()`, `main()`이다. 함수 이름은 달라도 역할은 유지한다.

## 7. 메인 루프 기준

```text
초기화
반복:
    종료 입력 확인
    현재 시간 계산
    재생 또는 1초 대기 상태 갱신
    화면 초기화
    현재 프레임 확대 출력
    화면 반영
    0.005초 이하 루프 지연
종료 처리
```

프레임 갱신과 그리기를 분리한다. 동작 전환 시 `frame_index`와 해당 시간 변수를 함께 초기화한다.

## 8. 검증 기준

### 기능 검증

- 실행 직후 첫 동작의 첫 프레임이 표시된다.
- 모든 동작이 정의된 순서로 재생된다.
- 각 동작이 정확히 5회 반복된다.
- 각 동작의 마지막 프레임이 1초 동안 유지된다.
- 마지막 동작 뒤 첫 동작으로 순환한다.
- 제목과 설명 문구가 프레임으로 표시되지 않는다.

### 화면 및 실행 검증

- 스프라이트가 확대되어 식별 가능하다.
- 프레임 전환 시 캐릭터 발 위치가 위아래로 튀지 않는다.
- 프레임 크기가 달라도 캐릭터 비율이 유지된다.
- 프레임이 화면 가장자리에서 잘리지 않는다.
- 프레임 전환이 멈추거나 지나치게 빠르지 않다.
- 해당 폴더에서 상대 이미지 경로로 실행된다.
- 창 닫기 동작으로 오류 없이 종료된다.

## 9. 완료 조건

다음 조건을 모두 만족하면 완료로 판단한다.

- `sonic_animation_viewer.py`가 Pico2D 환경에서 실행된다.
- `sonic-sprite.png`의 동작 프레임이 누락 없이 재생된다.
- 동작별 5회 반복과 동작 사이 1초 대기가 동작한다.
- 마지막 프레임 유지와 공통 기준선 배치로 동작이 자연스럽게 보인다.
- 마지막 동작 뒤 첫 동작으로 무한 순환한다.
- 확대된 화면에서 프레임과 동작을 확인할 수 있다.
- 창을 정상 종료할 수 있다.
